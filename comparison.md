# Numerical implementation comparisons

This document records the numerical comparisons performed for the
Wilson–clover, HISQ, and Möbius domain-wall support in LatticeQCD.jl. Numeric
comparisons record the values from every implementation, in addition to the
acceptance tolerance and pass count. The comparisons were run on 2026-08-25.

# Wilson–clover

## Operator convention

LTK and LatticeDiracOperators use the same Euclidean chiral gamma-matrix
convention. The LTK clover implementation is in
`Lattice-Tool-Kit/FERMIONwithClover/clover.f` and defines

```text
M_f = M_w + M_c
M_c = -i cSW kappa / 2 * sum_(mu,nu) sigma_(mu,nu) F_(mu,nu)
F_(mu,nu) = (Q_(mu,nu) - Q_(mu,nu)^dagger) / 8
```

LTK's HMC example uses `cSW = 1.5612`. This value is retained as the
historical default in the Wizard, but the generated TOML always writes cSW
explicitly because it is not a universal constant.

# HISQ

## LatticeQCD configuration and runtime conditions

HISQ is represented independently from one-link staggered fermions by
`HISQDiracConfig(mass, naik_epsilon)`. The implementation enforces the
requirements of the LatticeMatrices/LatticeDiracOperators HISQ path:

| Item | Requirement used in the tests |
|---|---|
| Gauge group | SU(3) |
| Gauge halo width | at least 3 |
| Fermion field family | staggered |
| Fermion mass | positive |
| Naik correction | finite and written explicitly by the Wizard |
| Fermion boundary conditions | (+1, +1, +1, -1) |

The HISQ operator itself constructs the level-1 Fat7 links, U(3) projection,
level-2 Fat7/Lepage links, and Naik links. The Wizard therefore does not add
an independent outer stout-smearing layer to HISQ.

# Möbius domain-wall

## Configuration and parameter convention

Möbius domain-wall fermions are represented by the concrete typed
configuration
`MobiusDomainwallDiracConfig(mass, domainwall_height, L5, b, c)`. The Wizard
writes all five parameters explicitly and keeps standard Shamir domain-wall
as a separate choice. The default Möbius parameters are mass 0.1, `M=-1`,
`L5=4`, `b=2`, and `c=1`.

LatticeMatrices/LDO use the legacy coefficients `b` and `c`. Their standard
Möbius coefficients are

```text
b_Grid = (b_LM + c_LM) / 2
c_Grid = (b_LM - c_LM) / 2
M5_Grid = -M_LM
```

Thus the Wizard default `b=2, c=1` corresponds to Grid's `b=1.5, c=0.5`.
Domain-wall fields are stored on a five-dimensional LatticeMatrices lattice;
LatticeQCD appends a periodic fifth-direction phase to the four physical
boundary phases. This fixes the otherwise invalid four-phase construction
for Möbius fields while leaving the Dirac operator's physical boundary
condition unchanged.
